# 01 — Architecture

All resources live in one GCP project behind one global external HTTPS load balancer. Names below are canonical; infrastructure code and other docs use them verbatim. `<club>` is a lowercase slug such as `galati`.

## Hostnames

| Host | Serves | Access | Backend |
|------|--------|--------|---------|
| `learning.mycodespace.ai` | Redirect to `open.` | Public | URL map redirect |
| `open.learning.mycodespace.ai` `/*` | Presentation site + request form | Public | `bb-open` (backend bucket + CDN) |
| `open.learning.mycodespace.ai` `/api/*` | Request submission and status | IAP, tenant `applicants` | `bs-open-api` → Cloud Run `open-api` |
| `auth.learning.mycodespace.ai` | Sign-in UI for all IAP resources | Public | `bs-auth` → Cloud Run `signin-ui` |
| `<club>.learning.mycodespace.ai` `/*` | Club SPA | IAP, tenants `supervisors` + `students-<club>` | `bs-<club>-web` → Cloud Run `club-web` |
| `<club>.learning.mycodespace.ai` `/api/*` | Club API | IAP, tenants `supervisors` + `students-<club>` | `bs-<club>-api` → Cloud Run `club-api` |

One wildcard certificate (`*.learning.mycodespace.ai` plus the apex) from Certificate Manager with DNS authorization covers every club, so adding a club needs no new certificate.

## Identity (summary; details in `02-identity.md`)

| Tenant | Provider | Who can create users | Mapped to |
|--------|----------|---------------------|-----------|
| `applicants` | Google | Anyone (self sign-up) | `bs-open-api` |
| `supervisors` | Google | Only emails pre-approved in Firestore (enforced by `beforeCreate` blocking function) | All `bs-<club>-*` |
| `students-<club>` | Email/password (synthetic emails) | Only the backend via Admin SDK (all client sign-up denied) | `bs-<club>-*` for that club only |

Tenant IDs are generated by Identity Platform; the names above are display names. Pulumi exports the generated IDs.

## Resource inventory

### Edge

| Resource | Type | Notes |
|----------|------|-------|
| `lmc-ip` | Global static IP | DNS A/AAAA records for apex and `*.` point here |
| `lmc-cert` | Certificate Manager certificate + map | Wildcard + apex, DNS authorization |
| `lmc-https-proxy` | Target HTTPS proxy | Uses the certificate map |
| `lmc-fwd-443`, `lmc-fwd-80` | Global forwarding rules | Port 80 redirects to HTTPS |
| `lmc-url-map` | URL map | One host rule per hostname; path matchers per host |
| `armor-open` | Cloud Armor edge policy | On `bb-open`: per-IP rate limit against scraping |
| `armor-backend` | Cloud Armor backend policy | On all `bs-*`: WAF preset, per-IP rate limits, tighter on `bs-open-api` and `bs-auth` |

### Backends

| Resource | Type | Target |
|----------|------|--------|
| `bb-open` | Backend bucket, CDN on | Bucket `<project>-open-static` (public read) |
| `bs-auth` | Backend service, no IAP | Serverless NEG → `signin-ui` |
| `bs-open-api` | Backend service, IAP (`applicants`) | Serverless NEG → `open-api` |
| `bs-<club>-web` | Backend service, IAP (`supervisors`, `students-<club>`) | Serverless NEG → `club-web` |
| `bs-<club>-api` | Backend service, IAP (`supervisors`, `students-<club>`) | Serverless NEG → `club-api` |

Each IAP-enabled backend service has an `iap.Settings` resource whose `access_settings.gcip_settings` lists its tenant IDs and `login_page_uri = https://auth.learning.mycodespace.ai`.

### Compute (all Cloud Run, ingress `internal-and-cloud-load-balancing`, explicit `max_instances`)

| Service | Purpose | Max instances (start) |
|---------|---------|----------------------|
| `signin-ui` | FirebaseUI-based sign-in page; picks tenant per target resource | 3 |
| `open-api` | `POST /api/request`, `GET /api/request/status` | 3 |
| `club-web` | NGINX, private bucket `<project>-club-static` mounted read-only (gen2) | 5 |
| `club-api` | All club endpoints; student management; admin endpoints | 10 |
| `workflow-worker` | Consumes request events; executes approvals; reconciler | 2 |
| `identity-hooks` | Identity Platform blocking functions (`beforeCreate`, `beforeSignIn`) | 5 |

`club-web` and `club-api` are shared across clubs (D-5). They learn the club from the IAP JWT audience (which backend service forwarded the request) and the token's tenant, never from the Host header alone.

### Data and async

| Resource | Type | Purpose |
|----------|------|---------|
| Firestore (Native) | Database | Collections: `account_requests`, `supervisors`, `students`, `clubs`, `rate_limits`, `audit` |
| `account-request-events` | Pub/Sub topic | Published on submission and on admin decision |
| `workflow-worker-sub` | Push subscription | Delivers to `workflow-worker` |
| `reconcile-hourly` | Cloud Scheduler job | Triggers the reconciler |
| `budget-kill-switch` | Billing budget + Pub/Sub notification | See `05-security-and-cost.md` |

## URL map

```
host learning.mycodespace.ai          → redirect https://open.learning.mycodespace.ai/
host open.learning.mycodespace.ai
    /api/*                            → bs-open-api
    default                           → bb-open
host auth.learning.mycodespace.ai
    default                           → bs-auth
host <club>.learning.mycodespace.ai   (one per club)
    /api/*                            → bs-<club>-api
    default                           → bs-<club>-web
unknown host                          → 404 (default service: a backend bucket holding only a 404 page)
```

## Adding a club (REQ-F-10)

One `ClubSite("<club>")` Pulumi component instance creates: the `students-<club>` tenant, `bs-<club>-web` and `bs-<club>-api` with their NEGs, two `iap.Settings`, the host rule, the Cloud Armor attachment, and a `clubs/<club>` Firestore seed document. No service redeploy.

## Why this satisfies the core requirements

- **REQ-NF-1:** Every request to `<club>.*` without a valid session for an allowed tenant is redirected or rejected by IAP. `club-web` and `club-api` never see it.
- **REQ-NF-2:** The only components reachable without an approved identity are the public bucket (CDN, rate-limited), the sign-in page (static, rate-limited), and `open-api` (requires a Google sign-in under D-1, throttled per identity). Every Cloud Run service has a hard instance cap, and a budget kill switch backs everything.
- **REQ-NF-3:** Identity Platform, IAP, the load balancer, and Firestore scale far beyond thousands of users; `max_instances` caps are the only knobs to raise.
